
如果说 **OOP**（面向对象编程）是把世界拆分成一个个**垂直的类**（比如 User、Order、Book），那么 **AOP** 就是在那这些类运行的时候，横着“切一刀”，在不修改原始代码的情况下，塞进去一些功能。

---

### 1. 核心直觉：什么是“切面”？

在开发 Java 后端项目时，你会发现有些逻辑是**重复出现**且与业务逻辑无关的。比如：

- **日志记录：** 每个方法开始前都要打印“开始执行”。
    
- **权限校验：** 每个接口进来都要判断用户登录了没（这里经常配合 SpEL 使用）。
    
- **事务管理：** 数据库操作前开启事务，操作完提交，报错了回滚。
    

如果每个方法里都写这些代码，你的业务逻辑会被这些“杂事”淹没。**AOP 的目的就是把这些“杂事”抽离出来，统一管理。**

---

### 2. AOP 的五个“八股文”核心概念

为了应对面试和实际开发，这五个词必须形成肌肉记忆：

1. **Aspect（切面）：** “杂事”的集合体。比如一个 `LogAspect` 类，里面专门写日志逻辑。
    
2. **Advice（通知）：** 具体的**动作**。是在方法执行前做？还是执行后做？（Before, After, Around）。
    
3. **Join Point（连接点）：** 程序运行中可以“插一脚”的所有地方（在 Spring 中通常指方法执行时）。
    
4. **Pointcut（切点）：** 具体的**筛选条件**。你不想给所有方法都加日志，只想给 `com.service` 包下的方法加，这个规则就是切点。
    
5. **Proxy（代理对象）：** AOP 的实现手段。Spring 会给你原来的 Bean 生成一个“替身”，你调用时其实是在调用替身，替身先做杂事，再调原件。
    

---

### 3. AOP 的工作流程（以“外卖系统”下单为例）

假设你有一个 `OrderService.createOrder()` 方法：

- **没有 AOP：** 你要在方法开头写 `checkPermission()`，中间写业务，最后写 `log()`。
    
- **有了 AOP：**
    
    1. 你定义一个切面。
        
    2. 告诉 Spring：只要是 `createOrder` 方法运行（**Pointcut**），就先执行权限检查（**Before Advice**）。
        
    3. Spring 在启动时（**ApplicationContext** 加载时），发现这个方法需要增强。
        
    4. Spring 动态创建一个代理对象。
        
    5. 当你调用 `createOrder` 时，实际上是代理对象在工作：**先查权限 -> 执行原逻辑 -> 打印日志**。



### 4.AOP术语

这里介绍一下 AOP 领域中的特性术语，防止自己下来看不懂文章：

- 通知（Advice）: AOP 框架中的增强处理，通知描述了切面何时执行以及如何执行增强处理，也就是我们上面编写的方法实现。
- 连接点（join point）: 连接点表示应用执行过程中能够插入切面的一个点，这个点可以是方法的调用、异常的抛出，实际上就是我们在方法执行前或是执行后需要做的内容。
- 切点（PointCut）: 可以插入增强处理的连接点，可以是方法执行之前也可以方法执行之后，还可以是抛出异常之类的。
- 切面（Aspect）: 切面是通知和切点的结合，我们之前在xml中定义的就是切面，包括很多信息。
- 引入（Introduction）：引入允许我们向现有的类添加新的方法或者属性。
- 织入（Weaving）: 将增强处理添加到目标对象中，并创建一个被增强的对象，我们之前都是在将我们的增强处理添加到目标对象，也就是织入（这名字挺有文艺范的）
