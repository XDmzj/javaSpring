
## 一、 什么是会话固定攻击？

在你的白马银行项目中，当用户一访问网站，后端服务器通常就会自动为这个浏览器创建一个 Session，并把它的唯一身份证 **`JSESSIONID`**（一串随机字符串）通过 Cookie 发给浏览器：

$$\text{浏览器} \xrightarrow{\text{携带 } \texttt{JSESSIONID=12345}} \text{Tomcat 服务器} \rightarrow \text{识别到用户状态}$$

**会话固定攻击的核心在于：** 黑客在攻击之前，自己先去白马银行网站转了一圈，获取了一个**完全合法的、但还没登录的** `JSESSIONID`（假设是 `HACK007`）。然后，黑客想方设法让**你**的浏览器也带上这个 `HACK007` 去登录。一旦你用这个 ID 登录成功，黑客就能拿着一模一样的 ID 直接登录你的账户！

## 二、 攻击原理（为什么能成功？）

会话固定攻击能够成功，根源在于很多传统的 Web 服务器（或程序员写的旧逻辑）有一个致命漏洞：

> **在用户登录成功前后，服务器没有强制销毁旧的会话，而是沿用了用户登录前的旧 `JSESSIONID`。**

我们可以把整个犯罪过程分为三个步骤：

1. **黑客“设局”：** 黑客访问白马银行，拿到一个没有登录的会话 ID：`JSESSIONID=HACK007`。
    
2. **黑客“下药”：** 黑客伪造一个白马银行的链接，并把这个 ID 拼在 URL 后面或者通过注入手段塞进链接里，例如：
    
    `http://localhost:8080/toLogin?jsessionid=HACK007`
    
    黑客把这个链接发给你（比如伪造成“银行周年庆抽奖”）。
    
3. **用户“上当”：** 你点击了这个链接，浏览器打开了真正的白马银行页面。由于链接里带着 `jsessionid=HACK007`，Tomcat 会误以为你的浏览器就是那个老用户，并全盘接受。
    
4. **用户“登录”：** 你在页面上输入了你的真实账号（`test`）和密码（`123456`），点击登录。
    
5. **漏洞爆发：** 后端执行了你的代码：`session.setAttribute("login", true);`。此时，服务器**把登录成功的状态，绑定在了旧的 `HACK007` 会话上**。
    
6. **黑客“收网”：** 黑客在自己电脑上，手动把浏览器的 Cookie 修改为 `JSESSIONID=HACK007`，然后刷新白马银行首页。由于这个会话刚刚被你“注入”了登录成功状态，黑客不需要输入密码，直接大摇大摆地进入了你的账户！
