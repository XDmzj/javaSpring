
# 设置二号拦截器流程

前面介绍了仅仅只有一个拦截器的情况，我们接着来看如果存在多个拦截器会如何执行，我们以同样的方式创建二号拦截器：

```java
public class SubInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
        System.out.println("二号拦截器：我是处理之前！");
        return true;
    }

    @Override
    public void postHandle(HttpServletRequest request, HttpServletResponse response, Object handler, ModelAndView modelAndView) throws Exception {
        System.out.println("二号拦截器：我是处理之后！");
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response, Object handler, Exception ex) throws Exception {
        System.out.println("二号拦截器：我是完成之后！");
    }
}
```

注册二号拦截器：

```java
@Override
public void addInterceptors(InterceptorRegistry registry) {
  	//一号拦截器
    registry.addInterceptor(new MainInterceptor()).addPathPatterns("/**").excludePathPatterns("/home");
  	//二号拦截器
    registry.addInterceptor(new SubInterceptor()).addPathPatterns("/**");
}
```

## 多级拦截器执行顺序

注意拦截顺序就是注册的顺序，因此拦截器会根据注册顺序依次执行，我们可以打开浏览器运行一次：

```
一号拦截器：我是处理之前！
二号拦截器：我是处理之前！
我是处理！
二号拦截器：我是处理之后！
一号拦截器：我是处理之后！
二号拦截器：我是完成之后！
一号拦截器：我是完成之后！
```

和多级Filter相同，在处理之前，是按照顺序从前向后进行拦截的，但是处理完成之后，就按照倒序执行处理后方法，而完成后是在所有的`postHandle`执行之后再同样的以倒序方式执行。


### 如果中间有人拦截（返回 `false`）会怎样？

这是多级拦截器最容易让人混淆的地方。

**核心规则：** 只有 `preHandle` 返回为 `true` 的拦截器，它对应的 `afterCompletion` 才会执行。而 `postHandle` 只要中间有任何一个拦截器返回 `false`（或者抛出异常），就**全部都不会执行**。

#### 场景示例：拦截器 A 返回 `true`，拦截器 B 返回 `false`

1. **拦截器 A** 的 `preHandle()` 执行 ──► 返回 `true`（登记成功，准备为其善后）。
    
2. **拦截器 B** 的 `preHandle()` 执行 ──► 返回 `false`（在此处被拦截）。
    
3. **Controller 方法** ──► **不执行**。
    
4. **所有拦截器** 的 `postHandle()` ──► **不执行**。
    
5. **拦截器 B** 的 `afterCompletion()` ──► **不执行**（因为 B 没通过）。
    
6. **拦截器 A** 的 `afterCompletion()` ──► **执行**（因为 A 之前返回了 `true`，必须负责清理资源）。

## 执行顺序的修改

### 默认顺序

在 Spring Boot 中，拦截器的执行顺序完全取决于你在配置类 `WebMvcConfigurer` 中**注册它们的先后顺序**。


```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Autowired
    private LogInterceptor logInterceptor;
    @Autowired
    private LoginInterceptor loginInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        // 先注册的先执行 preHandle
        registry.addInterceptor(logInterceptor)
                .addPathPatterns("/**");

        // 后注册的后执行 preHandle
        registry.addInterceptor(loginInterceptor)
                .addPathPatterns("/**");
    }
}
```

_在上面的配置中，`LogInterceptor` 的 `preHandle` 会先于 `LoginInterceptor` 执行。_



### 显式指定顺序
**显式指定顺序（更稳妥的做法）：** 如果担心代码调整导致注册顺序被打乱，你可以使用 `.order()` 方法显式指定优先级。**数值越小，优先级越高**（`preHandle` 越先执行）：



```java
registry.addInterceptor(logInterceptor).addPathPatterns("/**").order(1);
registry.addInterceptor(loginInterceptor).addPathPatterns("/**").order(2);
```
