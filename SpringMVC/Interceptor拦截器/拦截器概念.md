拦截器是整个SpringMVC的一个重要内容，拦截器与过滤器类似，都是用于拦截一些非法请求，但是我们之前讲解的过滤器是作用于Servlet之前，只有经过层层的过滤器才可以成功到达Servlet，而拦截器并不是在Servlet之前，它在Servlet与RequestMapping之间，相当于DispatcherServlet在将请求交给对应Controller中的方法之前进行拦截处理，它只会拦截所有Controller中定义的请求映射对应的请求（不会拦截静态资源），这里一定要区分两者的不同。

# 拦截器的核心应用场景

拦截器最主要的目的是**把公共的、与业务逻辑无关的代码抽离出来**，避免在每个 Controller 方法里重复编写。

- **登录检查 / 身份验证：** 检查用户是否登录，没登录就直接拦截并重定向到登录页面（这在几乎所有 Web 项目中都是刚需）。
    
- **权限验证：** 检查当前登录的用户是否有权限访问这个接口。
    
- **日志记录：** 统计请求的耗时、记录谁在什么时间访问了什么接口，用于后期性能优化或审计。
    
- **通用数据处理：** 在请求到达控制器前，统一在 `HttpServletRequest` 中注入一些通用参数。

# 拦截器的工作流程

在 Spring MVC 中，拦截器的核心是由 `HandlerInterceptor` 接口定义的，它提供了三个关键的拦截点（你可以把它想象成请求处理生命周期的三个钩子）：

1. **`preHandle()`（前置处理）：**
    
    - **时机：** 在 Controller 方法执行**之前**。
        
    - **作用：** 决定请求是否继续往下走。如果返回 `true`，请求继续放行；如果返回 `false`，请求在这里被中断，后续的 Controller 就不会被执行了。
        
2. **`postHandle()`（后置处理）：**
    
    - **时机：** 在 Controller 方法执行**之后**，但视图渲染**之前**（如果使用的是传统 Thymeleaf/JSP 模板）。
        
    - **作用：** 可以对 Controller 传回的 `ModelAndView` 进行修改（不过在现在流行的前后端分离、纯返回 JSON 的 `@RestController` 项目中，这个方法用得相对较少了）。
        
3. **`afterCompletion()`（完成处理）：**
    
    - **时机：** 整个请求处理完毕，视图/JSON 数据已经响应给用户**之后**。
        
    - **作用：** 无论是否发生异常都会执行，通常用来进行**资源清理**（比如清除 ThreadLocal 中的用户信息，防止内存泄漏）。

## 拦截器在整个MVC中的位置


1. **在 DispatcherServlet 之后：** 拦截器（Interceptor）是 Spring MVC 内部的组件，必须先经过 `DispatcherServlet` 接收到请求后，才会触发拦截器。
    
2. **在 HandlerMapping 之后：** `DispatcherServlet` 会先找 `HandlerMapping` 帮它**匹配**出当前请求对应的是哪个 Controller 方法，并把匹配出来的 Controller 和相关的拦截器一起打包，然后再按顺序执行拦截器。
    

为了让你一眼看清它们之间的套娃关系，我们来看看一个请求进来的**真实流转顺序**：

```
客户端请求 
   │
   ▼
1. Tomcat 容器 (Filter 过滤器在这里工作)
   │
   ▼
2. DispatcherServlet (前端控制器，Spring MVC 的入口)
   │
   ├─► 3. HandlerMapping (根据 URL 查找对应的 Controller 方法)
   │      │
   │      ▼ 返回一个【执行链】：包含目标 Controller + 相关的 Interceptors
   │
   ▼
3. 执行拦截器的 preHandle() 方法 ──(若返回 false)──► 直接中断返回
   │
   ▼
4. 执行 Controller 中的业务方法 (你的业务逻辑)
   │
   ▼
5. 执行拦截器的 postHandle() 方法
   │
   ▼
6. 渲染视图 / 转换 JSON 响应
   │
   ▼
7. 执行拦截器的 afterCompletion() 方法
```


## 拦截器能不能拦截静态资源？

**答案是：可以，但取决于你的配置。**

在 Spring MVC 的演进过程中，对待静态资源（如 `.js`, `.css`, `.png`）的拦截经历过变化：

#### 1. 为什么它能拦截到静态资源？

因为在 Spring Boot 中，默认的拦截路径配置通常是将 `DispatcherServlet` 映射到了根路径 `/`。这意味着**所有的请求**（包括请求控制器、也包括请求静态资源）都会先进入 `DispatcherServlet`。既然进了 `DispatcherServlet`，如果你的拦截器配置的是 `addPathPatterns("/")`，它就会去拦截静态资源。
