在现代的纯注解驱动（JavaConfig）开发中，我们完全脱离了 XML。以下是程序员需要负责编写的五个核心源代码元素。

---

### 一、 顶层入口：应用初始化类（替代 `web.xml`）

这是整个 Web 应用在 Tomcat 启动时的入口。程序员需要编写一个类去继承 Spring 提供的抽象类。

- **核心源码元素：** 继承 `AbstractAnnotationConfigDispatcherServletInitializer`
    
- **打在什么位置：** 独立类，通常放在 `config` 包下。
    
- **有什么用：** 告诉 Tomcat，整个项目基于注解配置，并指定 Spring MVC 的前端控制器（DispatcherServlet）拦截哪些 URL。
    

```java
package org.example.config;

import org.springframework.web.servlet.support.AbstractAnnotationConfigDispatcherServletInitializer;

public class MyWebAppInitializer extends AbstractAnnotationConfigDispatcherServletInitializer {

    // 指定根配置类（通常用于管理 Service, Data Source 等后端核心 Bean）
    @Override
    protected Class<?>[] getRootConfigClasses() {
        return new Class<?>[] { RootConfig.class };
    }

    // 指定 Spring MVC 的配置类（管理 Controller, 视图解析器等 Web 相关 Bean）
    @Override
    protected Class<?>[] getServletConfigClasses() {
        return new Class<?>[] { WebConfig.class };
    }

    // 指定 DispatcherServlet 拦截的 URL 路径
    @Override
    protected String[] getServletMappings() {
        return new String[] { "/" }; // "/" 代表拦截除了 .jsp 之外的所有请求
    }
}
```

### 二、 核心中枢：配置类（替代 `spring-mvc.xml`）

这个类负责组装整个 Spring MVC 的运行环境，并允许程序员进行个性化定制。

- **常见注解及位置：**
    
    - **`@Configuration`**：打在**类名上**。声明这是一个配置类，Spring 会将其作为 Bean 定义的来源。
        
    - **`@ComponentScan("...")`**：打在**类名上**。指定组件扫描路径，自动将该包及子包下的 `@Controller`、`@Component` 等注解类注册为组件（Bean）。
        
    - **`@EnableWebMvc`**：打在**类名上**。开启 Spring MVC 的核心功能（自动在底层注册默认的请求映射和适配器）。
        
    - **`@Bean`**：打在配置类的**方法上**。将该方法的返回值对象注册为 Spring 容器中的 Bean（常用于注册自定义的视图解析器或消息转换器）。
        
- **实现接口：** `implements WebMvcConfigurer`。通过重写其默认方法来定制全局行为（如拦截器、静态资源、跨域）。
    

Java

```
package org.example.config;

import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.EnableWebMvc;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.ResourceHandlerRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;
import org.example.interceptor.LoginInterceptor;

@Configuration
@ComponentScan("org.example")
@EnableWebMvc
public class WebConfig implements WebMvcConfigurer {

    // 重写方法：注册自定义拦截器
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new LoginInterceptor())
                .addPathPatterns("/api/**")       // 拦截路径
                .excludePathPatterns("/api/login"); // 放行路径
    }

    // 重写方法：配置静态资源放行
    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        registry.addResourceHandler("/static/**")
                .addResourceLocations("/static/");
    }
}
```

### 三、 关卡防御：自定义拦截器

当请求匹配到具体的 Controller 之前，程序员可以通过拦截器进行权限或日志处理。

- **实现接口：** `implements HandlerInterceptor`
    
- **有什么用：** 提供前置、后置的过滤能力。
    
- **核心重写方法：**
    
    - `preHandle`：在 Controller 方法执行**前**运行。返回 `true` 放行，返回 `false` 中断请求。
        
    - `postHandle`：在 Controller 方法执行**后**、视图渲染**前**运行。
        
    - `afterCompletion`：在整个请求彻底**结束**（视图渲染完毕或数据已响应）后运行，用于资源清理。
        

Java

```
package org.example.interceptor;

import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.web.servlet.HandlerInterceptor;

public class LoginInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
        // 程序员编写具体的校验逻辑
        Object user = request.getSession().getAttribute("user");
        if (user == null) {
            response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
            return false; // 中断流程
        }
        return true; // 放行
    }
}
```

### 四、 业务入口：控制器（Controller）

这是程序员接触最频繁的层面，用于定义具体的 HTTP 接口和接收请求参数。

#### 1. 类级别的注解

- **`@Controller`**：打在**类名上**。声明这是一个 Spring MVC 控制器 Bean。
    
- **`@RestController`**：打在**类名上**。它是 `@Controller` + `@ResponseBody` 的组合。声明该类中所有方法的返回值都会直接作为 HTTP 响应体（输出 JSON/文本），不再走视图解析器，**现代前后端分离开发必用**。
    
- **`@RequestMapping("/...")`**：可打在**类名上**。定义该控制器下所有接口的通用公共父路径（如 `/book`）。
    

#### 2. 方法级别的映射注解

- **`@GetMapping`、`@PostMapping`、`@PutMapping`、`@DeleteMapping`**：打在**方法名上**。限定该方法处理的 URL 路径和特定的 HTTP 请求方法。
    

#### 3. 方法参数级别的接收注解（用于精细化控制参数绑定）

- **`@RequestParam`**：打在**方法参数前**。用于接收标准的 Query 参数或 Form 表单数据。可设置默认值或指定必填。
    
- **`@PathVariable`**：打在**方法参数前**。用于接收 RESTful 风格中路径上的动态变量。
    
- **`@RequestBody`**：打在**方法参数前**。极为重要，用于接收前端发来的 **JSON 报文**，并将其自动反序列化为 Java 对象。
    

Java

```
package org.example.controller;

import org.example.dto.BookDTO;
import org.springframework.web.bind.annotation.*;
import java.util.List;

@RestController
@RequestMapping("/api/books") // 提取公共父路径
public class BookController {

    // 1. 路径变量示例：GET /api/books/102
    @GetMapping("/{id}")
    public String getBookById(@PathVariable("id") Long id) {
        return "查询到ID为 " + id + " 的图书";
    }

    // 2. Query参数示例：GET /api/books/search?keyword=Java&page=1
    @GetMapping("/search")
    public String searchBooks(@RequestParam(value = "keyword", required = false) String keyword,
                              @RequestParam(value = "page", defaultValue = "1") int page) {
        return "搜索关键词: " + keyword + ", 当前页码: " + page;
    }

    // 3. JSON反序列化示例：POST /api/books 并在 Body 中携带 JSON
    @PostMapping
    public String createBook(@RequestBody BookDTO bookDTO) {
        // 此时 bookDTO 已经被自动填充了前端传来的数据
        return "成功保存图书: " + bookDTO.getTitle();
    }
}
```

### 五、 数据载体：数据传输对象（DTO / Entity）

为了配合 `Controller` 层规范地接收和返回数据，程序员需要编写纯粹的 Java 类（POJO）作为数据的承载实体。

- **特点：** 不需要任何 Spring 的核心组件注解，只需提供属性的 `getter/setter`（通常配合 Lombok 插件）。
    
- **配合 `@RequestBody` 时的运作：** 当 Controller 参数带有 `@RequestBody BookDTO bookDTO` 时，Spring 底层会自动调用消息转换器，将 JSON 报文中的键（Key）通过反射一一对应赋值到该类的属性中。
    

Java

```
package org.example.dto;

import lombok.Data; // 自动生成 getter/setter/toString

@Data
public class BookDTO {
    private Long id;
    private String title;
    private String author;
    private Double price;
}
```

### 🚀 总结：程序员的代码是怎么串联起来的？

1. Tomcat 启动时，率先加载了 **`MyWebAppInitializer`**，它告诉 Tomcat：“我要使用基于 **`WebConfig`** 的全注解 Spring 环境”。
    
2. Spring 容器初始化 **`WebConfig`**，读取到了里面的扫描包路径，顺着路径把带有 **`@RestController`** 的 **`BookController`** 实例化为 Bean。
    
3. 随后，Spring 提取 **`WebConfig`** 中重写的 `addInterceptors` 方法，将程序员编写的 **`LoginInterceptor`** 挂载到执行链中。
    
4. 当浏览器发起 `POST /api/books` 携带 JSON 时，进入拦截器通过后，直达 `createBook` 方法。参数中的 **`@RequestBody`** 自动激活，把 JSON 灌入程序员定义的 **`BookDTO`** 实例中，方法开始执行业务逻辑。
