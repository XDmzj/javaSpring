# 三层架构

### 1. 表现层（Presentation Layer）

- **职责：** 负责与用户进行交互。接收客户端（浏览器、手机端）传来的请求，参数校验，并将处理结果（HTML 页面或 JSON 数据）返回给用户。
    
- **技术体现：** 在你的项目中，就是 **Spring MVC**（包括 Controller、Interceptor 等）。
    

### 2. 业务逻辑层（Service Layer）

- **职责：** 系统的“核心大脑”。负责处理复杂的业务逻辑（如：计算、判断、组装数据、事务控制）。它夹在表现层和数据访问层中间，起到承上启下的核心作用。
    
- **技术体现：** 编写的 Service 接口及相应的实现类（`ServiceImpl`），通常配合 Spring 的 `@Service` 和 `@Transactional` 注解。
    

### 3. 数据访问层（Data Access Layer / DAO）

- **职责：** 专职与数据库“打交道”。负责数据的增删改查（CRUD），不包含任何业务逻辑。
    
- **技术体现：** 在现主流 Java 栈中，通常使用 **MyBatis / MyBatis-Plus** 的 Mapper 接口，或者 Hibernate/JPA。

# 三层架构与 MVC 的融合与映射

| **三层架构**   | **对应 MVC 组件**        | **在 Java 项目中的具体包名/类名**              | **核心职责**                                |
| ---------- | -------------------- | ----------------------------------- | --------------------------------------- |
| **表现层**    | **Controller** (控制器) | `com.example.controller.*`          | 接收请求，调用 Service，决定去哪个 View 或者返回什么 JSON。 |
| **表现层**    | **View** (视图)        | `resources/templates/*.html`        | Thymeleaf 模板或 HTML 页面，负责展示数据给用户。        |
| **表现层/全局** | **Model** (模型)       | `com.example.entity.*` 或 `VO / DTO` | 承载和传输数据的实体对象或业务对象。                      |
| **业务逻辑层**  | （属于 M 的一部分）          | `com.example.service.*`             | 执行核心业务，控制事务。                            |
| **数据访问层**  | （属于 M 的一部分）          | `com.example.mapper.*`              | 执行 SQL 语句，操作物理数据库。                      |

# 一个请求在三层架构中的完整流转

以一个具体的业务为例——**“用户在前端点击按钮，查询图书列表”**。

看看这个请求是如何横穿整个三层架构的：

1. **客户端触发：** 用户在网页上点击“查看图书”。前端通过 **Axios** 发送一个异步请求到后端路径 `/book/list`。
    
2. **表现层拦截与分发：** * 请求到达 Tomcat，先经过你的 `MainInterceptor`（拦截器）进行登录检查。
    
    - 放行后，由 `DispatcherServlet` 分发给 `BookController` 的 `list()` 方法。
        
    - `BookController` 收集并校验前端传来的参数。
        
3. **调用业务层：** * `BookController` 自己不查数据库，它调用 `BookService.queryAllBooks()`。
    
    - `BookServiceImpl` 收到指令，执行业务逻辑（比如：判断当前用户等级是否能看这些书、记录查询日志等）。
        
4. **调用数据层：** * `BookServiceImpl` 进一步调用 `BookMapper.selectAll()`。
    
    - MyBatis 框架执行对应的 SQL 语句，从 MySQL 数据库中查出原始的二进制数据，并自动封装成 `List<Book>` 实体对象返回。
        
5. **层层原路返回：**
    
    - `BookMapper` 把 `List<Book>` 向上返回给 `BookService`。
        
    - `BookService` 处理完后，继续向上返回给 `BookController`。
        
6. **表现层渲染/响应：** * **如果是前后端分离：** `BookController` 带有 `@ResponseBody`，将 `List<Book>` 序列化为 JSON 字符串，Axios 接收后在局部刷新网页。
    
    - **如果是传统不分离：** `BookController` 返回 `new ModelAndView("index")`，将数据塞入 Model，由 Thymeleaf 视图解析器找到 `templates/index.html` 渲染成带有数据的 HTML，最后丢给浏览器。

---

三层架构的核心精髓在于：**解耦（Decoupling）**。

- **高内聚，低耦合：** 每一层只关心自己的事情。Controller 只管接收参数，Service 只管写业务，Mapper 只管写 SQL。
    
- **极强的可维护性和扩展性：**
    
    - 假设哪天老板说：“咱们不用 MySQL 了，全面切换到 Oracle 数据库！” ── 你只需要重写数据访问层（Mapper 里的 SQL），表现层和业务层的代码**一个字都不用改**。
        
    - 假设哪天前端同学说：“咱们页面不用 Thymeleaf 了，全面改成 Vue 前后端分离！” ── 你只需要把 Controller 上的 `@Controller` 改成 `@RestController`，让它返回 JSON 即可，底层的 Service 和 Mapper **完全不需要变动**。
