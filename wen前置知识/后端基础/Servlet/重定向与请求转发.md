
# 重定向

### 重定向的工作原理（“两次请求”模型）

重定向的过程就像是你去银行办事：

1. **第一步（Request 1）**：你（浏览器）去 A 窗口说：“我要取钱”。
    
2. **第二步（Response 1）**：柜员（服务器）说：“取钱去 B 窗口，这是 B 的地址”。（状态码 **302**）
    
3. **第三步（Request 2）**：你拿着地址，转身走向 B 窗口说：“我要取钱”。
    
4. **第四步（Response 2）**：B 柜员帮你办好了业务。（状态码 **200**）
    

**关键点：** 浏览器地址栏会发生**变化**，且一共产生了**两次**完全独立的 HTTP 请求。

### 在 Java Servlet 中如何实现

在 Servlet 中，我们使用 `response` 对象来触发重定向：

```Javascript
// 登录成功后，重定向到主页
response.sendRedirect("index.jsp");
```

当你执行这行代码时，服务器其实给浏览器发回了一个特殊的响应：

- **状态码**：302 Found（临时移动）或 301 Moved Permanently（永久移动）。
    
- **响应头**：`Location: index.jsp`。
    



## 为什么重定向会丢失数据？

因为重定向产生了**第二次请求**。

你在第一个 Servlet 里通过 `request.setAttribute("user", "test")` 存的数据，在重定向后就消失了，因为第二个请求是一个全新的 `request` 对象。

**解决方法：**
- 如果是重定向，通常把数据存在 **Session** 里，或者拼在 URL 后面：`index.jsp?msg=success`。
    

## 常见的重定向状态码

|**状态码**|**含义**|**场景**|
|---|---|---|
|**301**|永久重定向|网站换了新域名，旧域名永久废弃。对 SEO 友好。|
|**302**|临时重定向|**登录跳转**最常用。这次跳过去，下次访问还是找原地址。|
|**303**|查看其他位置|强制让浏览器用 `GET` 访问新地址（常用于 POST 后的跳转）。|
|**307**|临时重定向|与 302 类似，但要求浏览器不改变请求方法（POST 保持 POST）。|

## 什么时候该用重定向？

1. **登录成功后**：这是最经典的场景。为了防止用户按 F5 刷新页面导致重复提交表单（产生多笔订单或重复登录），必须重定向到一个新页面。
    
2. **跨站跳转**：比如你的项目里有一个“去官网”的按钮。
    
3. **资源位置改变**：你修改了项目的目录结构，旧的 URL 为了兼容需要导向新的 URL。

# 请求转发

## 请求转发的工作原理（“一次请求”模型）

1. **客户端发送请求**：浏览器向服务器发起一次 HTTP 请求。
    
2. **服务器内部流转**：Servlet A 处理了一部分逻辑，调用 `request.getRequestDispatcher("ServletB").forward(request, response)`。
    
3. **直接响应**：Servlet B 处理完后，直接将结果写入响应体，发回给浏览器。
    

**核心特征：**

- **地址栏不变**：浏览器以为一直是 Servlet A 在提供服务。
    
- **共享 Request**：因为只有一次请求，Servlet A 和 Servlet B 共享同一个 `request` 对象。你可以通过 `request.setAttribute()` 实现数据传递。

# 重定向vs请求转发

### 重定向 vs 请求转发 (Forward)

这是 Java 后端面试必考题。你觉得 Servlet 麻烦，很大程度上是因为要区分这两者。

| **特性**        | **重定向 (Redirect)** | **请求转发 (Forward)** |
| ------------- | ------------------ | ------------------ |
| **执行位置**      | 浏览器端行为（客户端）        | 服务器端内部行为           |
| **HTTP 请求次数** | **2次**             | **1次**             |
| **地址栏变化**     | **会变**（显示新地址）      | **不变**（显示原地址）      |
| **数据共享**      | 丢失原来的 `request` 对象 | 共享同一个 `request` 对象 |
| **跳转范围**      | 可以跳转到任何网站（如百度）     | 只能跳转到当前 Web 应用内部   |
| **效率**        | 略低（多了一次网络往返）       | 高（服务器内部跳转）         |
|               |                    |                    |
### 2. 重定向 vs 请求转发：深度对比

这是每个 Java 后端程序员必须烂熟于心的对照表：

|**特性**|**请求转发 (Forward)**|**重定向 (Redirect)**|
|---|---|---|
|**定义**|服务器内部的资源跳转|浏览器重新发起请求|
|**请求次数**|**1次**|**2次**|
|**浏览器地址栏**|**保持不变**|**显示新地址**|
|**数据传递**|简单（通过 `request` 对象传递）|复杂（需通过 `session` 或 URL 参数）|
|**跳转范围**|只能跳转到**当前应用**内部资源|可以跳转到**互联网任何地方**|
|**关键字**|`RequestDispatcher`|`sendRedirect`|
|**发生位置**|服务器端（Server-side）|客户端（Client-side）|
